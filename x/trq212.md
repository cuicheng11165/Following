### Opinions and takes

- 模型变聪明后需要更少指令与示例；示例会过度约束自由形式输出——新模型应「修剪上下文、多留运行空间」。
- Skills 动态加载（默认只见名称与触发条件）；多数 skill.md 过大；scripts + progressive disclosure 更好。
- Opus 擅 coding，Fable 是更聪明的 generalist——基准测试不一定反映这一点。
- 手游成功更受局内经济与变现迭代约束；coding agent 可加速找对经济模型，但仍是真工作。
- 先做 mockup/schema/PoC 原型，避免花大量 token 才发现不要该输出。
- 文件 harness 类工具长期可能消失（模型能力上升）。
- 「ralph loop」过窄将退出，但日程/事件驱动的 loop（如 Claude Tag）很重要。
- 软件工程是自动化的职业：领域知识应编码进 CLAUDE.md / skills / 基建。
